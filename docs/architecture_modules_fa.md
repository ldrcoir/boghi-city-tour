# معماری ماژولار بوقی — «موتور پایه + پک محتوا»

هدف: این نسخه فقط یک «تست بازار» نیست، **پایه‌ی موتور بازی‌های ماشینی** ماست.
هر بازی بعدی (همان بازار یا نسخه انگلیسی/آمریکایی، حتی پورت استیم) باید با تعویض پک محتوا ساخته شود، نه از صفر.

## ۱) نقشه‌ی ماژول‌ها (جداسازی موتور از محتوا)

```
game/
├── engine/            ← «موتور پایه» — هیچ فارسی/فرهنگی داخلش نیست
│   ├── race_core      (فیزیک، پیست، برخورد، سکه، خط پایان)
│   ├── cutscene_core  (banner → enter → line → bounce → move → end)
│   ├── dialogue_core  (جعبه تایپ‌رایتر RTL/LTR خودکار، صدا، پرتره)
│   ├── audio_core     (موسیقی/افکت/صدا، بدون اسم فایل هاردکد)
│   ├── ads_adapter    (رابط تبلیغ: Tapsell/AdMob/Null — قابل تعویض)
│   ├── net_core       (آنلاین + جایگزینی AI بعد از تایم‌اوت)
│   └── vault          (BVAULT: رمز ChaCha20، پخش داخلی)
├── content/fa_ir/     ← «پک محتوای فارسی/ایرانی» (همین بازی بوقی)
│   ├── characters.json (بوقی، نیسان، سیسبلو... + رنگ/تن صدا)
│   ├── story/episodes/ (اپیزودها: متن + صدا)
│   ├── levels/         (۵۰ مأموریت فصل ۱)
│   ├── strings_fa.json (تمام متن‌های UI)
│   ├── art/            (اسپرایت‌ها، پس‌زمینه‌ها)
│   └── audio/          (موسیقی، صدای موتور، صدای دیالوگ)
└── content/en_us/     ← بعداً: کاراکترها/طنز/دیالوگ آمریکایی، همان موتور
```

## ۲) قوانین نوشتن کد (برای ماژولار ماندن)

1. **هیچ متن فارسی داخل engine/** — همه از `strings_XX.json` می‌آید
2. **هیچ اسم کاراکتر/مرحله‌ای داخل موتور** — موتور فقط «بازیگر» و «بیت» می‌شناسد
3. **صدا/دیالوگ = داده، نه کد** — اپیزود JSON است؛ صدا بعداً به همان JSON وصل می‌شود
4. **تبلیغ فقط از `ads_adapter`** — تعویض شبکه = تعویض یک فایل
5. **جهت متن (RTL/LTR) از locale پک خوانده شود** نه تنظیم دستگاه
6. هر پک محتوا یک `pack.json` دارد: نام، زبان، جهت، لیست اپیزودها/مراحل

## ۳) مسیر نسخه بین‌المللی (وقتی خواستیم)

- پک `en_us` با کاراکترهای جدید (مثلاً «Bucky» برای بازار آمریکا) — طنز محلی، نه ترجمه‌ی طنز ایرانی
- استیم: گودو اکسپورت ویندوز/لینوکس/مک دارد؛ فقط `ads_adapter → NullAdapter` و کنترل کیبورد کامل + دستاورد Steam از طریق GodotSteam
- متن‌ها کلیدواژه‌محورند → ترجمه به هر زبان = یک فایل strings جدید

## ۴) تحقیق ویژگی‌های بازی‌های ماشینی جهانی (برای نسخه آینده)

از تحقیق بازار جهانی (PCMag/Minireview/Mistplay 2026) — آنچه بازی‌های موفق دارند:
- **دریفت واقعی** (CarX): فیزیک لغزش + امتیاز دریفت — بزرگ‌ترین خواسته‌ی سبک
- **بوست/نیترو** و جمع‌آوری سوخت (Horizon Chase)
- **گاراژ/تینت**: موتور، لاستیک، رنگ، دکال — عمق پیشرفت
- **کری‌ر mode با فصل‌ها** — ما داریم (فصل تهران ۵۰ مأموریت)
- **چندنفره آنلاین** — داریم (با AI fallback)
- **چالش روزانه/لیدربورد** — جای افزودن
- اولویت برای «Need for Speed-وار» سبک خیابانی: پلیس‌وتعقیب، تیون عمیق، شب/روز — قابل ساخت روی همین race_core (فاز ۲+)

## ۵) وضعیت فعلی کد نسبت به این معماری

| ماژول | وضعیت |
|---|---|
| cutscene_core + dialogue_core | ✅ کار می‌کند (story.gd/cutscene.gd/dialogue.gd) |
| race_core | ✅ کار می‌کند (game.gd) |
| net_core با AI fallback | ✅ (online_race.gd) |
| vault BVAULT | ✅ (asset_vault.gd) |
| ads_adapter | ⏳ رابط ساخته می‌شود وقتی AppKey آماده شد |
| جداکردن متن فارسی از موتور | ⏳ در حال مهاجرت به strings پک |
